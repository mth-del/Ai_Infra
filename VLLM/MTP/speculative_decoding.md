# 投机推理（Speculative Decoding）

## 1. 核心问题

**大模型推理为什么慢？**

LLM 自回归推理的本质是串行生成：每次只能生成 1 个 token，生成完才能生成下一个。

但慢的根因不是算力不够，而是**访存瓶颈（Memory Bound）**：

```text
生成 1 个 token = 把整个模型权重从显存读到计算单元一次
GPU 的算力大量被闲置，在等数据
```

生成 100 个 token = 读 100 次完整权重，每次读权重的时间 >> 实际矩阵乘法的时间。

## 2. 投机推理的核心洞察

**验证多个 token 和验证 1 个 token，耗时几乎相同。**

大模型做 forward pass 时，天然支持并行处理整个序列（和 prefill 阶段一样）。

所以：

```text
大模型验证 1 个 token    耗时 ≈ T
大模型并行验证 5 个 token 耗时 ≈ T（略多一点）
```

这是投机推理加速的根本原因。

## 3. 推理流程

```text
Step 1：草稿模型（Draft Model）串行生成 k 个候选 token
        token1 → token2 → token3 → token4 → token5（很快，模型参数量小）

Step 2：大模型（Verifier）一次 forward pass 并行验证这 k 个 token
        [token1, token2, token3, token4, token5] → 同时判断每个是否正确

Step 3：找到第一个错误位置，接受之前所有正确的 token
        假设前 4 个对，第 5 个错 → 本轮净赚 4 个 token
        大模型在第 5 个位置重新生成正确 token
```

## 4. 为什么小模型不是额外负担？

```text
小模型参数量通常只有大模型的 1/10 ~ 1/100，速度极快。
小模型的推理开销 << 节省下来的大模型推理次数。
只要草稿的接受率（acceptance rate）足够高，整体就是赚的。
```

关键指标：

```text
接受率（acceptance rate）：草稿 token 被大模型接受的比例，越高越好
草稿模型速度：越快越好，推荐使用同系列的小版本模型（如同架构不同参数量）
```

## 5. 加速比分析

实际效果可以达到 **2x ~ 3x** 的端到端加速。

影响加速比的两个核心因素：

```text
1. 草稿接受率 —— 草稿越准，每轮接受的 token 越多，加速越显著
2. 大小模型速度差 —— 小模型越快，整体代价越低
```

如果接受率极低（草稿总是错），每轮仍然只接受 1 个 token，等价于没有加速，反而多跑了一次小模型。

## 6. 形象类比

```text
老方式：老板每次只看 1 份文件，批完才给下一份。

投机方式：助理先预处理 5 份草稿，老板一次批阅 5 份。
          助理（小模型）的时间成本远小于老板（大模型）省下的时间。
```

## 7. 典型实现

```text
草稿模型：同系列参数量更小的模型（如 Llama-3-70B 用 Llama-3-8B 做草稿）
          或专门训练的轻量 Draft 模型

验证方式：token-level 接受/拒绝，拒绝时从大模型的分布中重新采样，保证输出分布不变
```

核心保证：**投机推理的输出分布和大模型单独推理完全等价**，不会损失质量。

## 8. MTP（Multi-Token Prediction）

### 8.1 基本概念

传统 LLM 训练是**单 token 预测**：每次只预测序列中的下一个 token。

MTP 是指模型在训练时**同时预测未来多个 token**：

```text
传统：输入 [How, can, I]  → 只预测下一个 "help"
MTP：输入 [How, can, I]  → 同时预测 "help", "you", "with"
```

### 8.2 来源：DeepSeek-V3 的预训练技巧

MTP 最近因 DeepSeek-V3 而广为人知。DeepSeek-V3 在预训练时为主模型额外添加了 MTP Head：

```text
主模型输出层：  预测 t+1
MTP Head 1：   额外预测 t+2
MTP Head 2：   额外预测 t+3
```

```text
训练时：MTP loss 作为辅助损失，增强模型对未来上下文的感知能力
推理时：MTP 头直接复用为草稿模型，实现投机推理加速
```

### 8.3 MTP 和 Speculative Decoding 的关系

```text
训练阶段（MTP）：
  额外 MTP Head 学会预测未来多个 token
  副产品：这个 MTP Head 本身就是一个优质草稿模型

推理阶段：
  MTP Head 生成 k 个草稿 token（不需要额外单独的小模型）
  主模型并行验证
  实现投机推理加速
```

EAGLE 启发了 DeepSeek-V3 的 MTP 预训练，DeepSeek-V3 的 MTP 又反过来启发了 EAGLE-3 的架构设计，两者相互启发。

### 8.4 与传统投机推理的对比

```text
传统投机推理：小模型预测草稿，大模型验证
  草稿模型来源：单独训练的小模型
  分布一致性：小模型和主模型可能存在分布差异
  部署成本：需要维护两个模型

MTP 投机推理：主模型自带 MTP Head 作为草稿模型
  草稿模型来源：主模型自带的 MTP Head
  分布一致性：天然对齐，接受率更高
  部署成本：只需一个模型
```

### 8.5 一句话总结

```text
MTP = 训练时让模型同时预测多个未来 token，推理时把这个能力复用为草稿模型，
无需额外小模型即可实现投机推理加速。
```

## 9. 面试表达

```text
投机推理的核心思路是：利用大模型并行验证多个 token 的开销和验证 1 个几乎相同这一特性，
用小模型批量生成草稿候选，再由大模型一次 forward 并行验证，
接受正确的 token，拒绝错误的位置并由大模型重新生成。

整体加速比取决于草稿接受率和大小模型速度差，
实践中可以达到 2x~3x 的端到端提速，且不改变最终输出分布，质量无损。
```

投机采样：其实就是用一个草稿模型先进行一个预测，预测完之后。用一个父模型进行验证。中间我思考过一个问题就是，为什么验证就会快一点，原因就是LLM预测过程都是一个token一个token的进行预测的，也就是token是一个一个产生的。这样其实是很耗费时间的，利用草稿模型draft model，参数量是父模型的1/10，其推理速度也会大幅度的提升。

如果先用draft model产生多个tokens,然后用父模型进行验证，其实最后的推理速度都是一样的。

投机推理步骤：
1.草稿模型
2.辅助层：在大模型基础上加上一些头层，目的就是能够生成更多的字符
3，数据匹配：利用历史数据/模板，通过规则匹配的方式生成字符，然后用大模型进行校验，如ngram、suffix decoding
